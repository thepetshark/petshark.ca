The pin bounce when tapped

This study explores a vertical "bounce" as touch feedback when a player taps a 2D marker: today's pickups are destroyed instantly, so a bounce would be cut off before it played, but that changes once objects fade in and out (animals first), leaving time for one to run. Three shapes to choose from, each stated in pixels of a 390-wide portrait screen and in seconds, playing on the game's real map at the three zooms. A quiet ring marks where the tap landed so the cause of each bounce is visible.

Picked, 23 September: squash and hop and settle, drawn as the fourth row: shape 3 whole, then shape 2's small second bounce. Every number stays a setting.

Motion is vertical only; every pin returns exactly to where it stood. Drawn over map screenshots of 2026-09-20, through today's flat interface. A tap plays automatically every 2 seconds, moving to the next pin; use the controls to pause or slow it down.

How each would be built

Every number above is a setting, not a fixed rule, so it can be tuned after choosing a shape.

piecebuilt as
The bounce itselfAn extra upward screen-pixel offset added in WorldMarkerCanvas.Place, computed from the time since the tap; the pin's own local position is never touched, so it still tracks the world point it marks.
The curveA small easing curve (a sine bell, or two in sequence for the settle) evaluated from elapsed time; no physics step, no per-frame accumulation, so it cannot drift.
The squashA non-uniform local scale on the pin's canvas RectTransform, applied only while the shape calls for it, always anchored at the pin's own tip so the tip never moves off the point it marks.
SettingsClamped fields on WorldMarkerSettings (height, duration, and the settle or squash amounts), one set per chosen shape, in pixels of the 390-wide reference canvas so they scale with the interface.
The tap momentRead from the same input event that already resolves which marker was hit; the bounce starts the frame the tap is recognised, not on pointer-up.
